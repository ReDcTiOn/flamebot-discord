# FlameBot

Боты для Discord-сервера RUST-сообщества и общая веб-панель управления.

В составе четыре бота:

- **Scrap Rank** — опыт за общение в чате, ранги по уровням строительства (Голый → Солома → Дерево → Камень → Металл → МВК), репутация через `/rep` и магазин за скрап.
- **Онлайн серверов** — для каждого игрового сервера отдельный Discord-бот показывает в статусе онлайн («Онлайн: 120/200 игроков», «Сервер запускается», «Сервер выключен»). Данные берутся по RCON командой `serverinfo`.
- **Розыгрыши** — розыгрыши с кнопкой «Участвовать»: итоги в назначенное время, только для бустеров по желанию, промокоды победителям в личные сообщения.
- **Карты вайпов** — под расписание вайпов заказывает карты на RustMaps, оценивает их, даёт выбрать (или подбирает сам), заливает в S3, шлёт анонс в Discord и записывает ссылки в задачи вайпа Pterodactyl. Управление — в панели и кнопками в Telegram.

Панель общая для всех ботов: вход, доступ, журнал действий и данные сервера у них общие, а у каждого бота свой раздел.

## Структура

```
apps/
  rating-bot/   бот Scrap Rank (discord.js)
  online-bot/   бот онлайна серверов (discord.js + WebRCON)
  giveaway-bot/ бот розыгрышей (discord.js)
  maps-bot/     бот карт вайпов (RustMaps, S3, вебхук Discord, Pterodactyl, Telegram)
  panel/        веб-панель (Next.js), вход через Discord
packages/
  core/         схема базы (Prisma), общие правила: ранги, проверка ролей, валидация настроек
```

Бот и панель общаются только через PostgreSQL. Панель не знает токен бота, бот не знает секрет OAuth.

## Команды бота

| Команда | Что делает |
|---|---|
| `/profile [игрок]` | картинка-карточка: ранг, прогресс, скрап, репутация, бейджи, место в топе. Вид настраивается в панели, раздел «Карточка профиля» |
| `/top [по]` | топ-10 по опыту, репутации или скрапу |
| `/rep игрок` | +1 к репутации (с ограничениями от накрутки) |
| `/shop` | магазин: роли, личная роль, бейджи |

## Бот розыгрышей

Команды доступны тем, у кого есть право «Управлять сервером». Другим ролям их можно открыть в настройках сервера → «Интеграции».

| Команда | Что делает |
|---|---|
| `/розыгрыш создать` | новый розыгрыш: приз, число победителей, дата и время итогов, только для бустеров, промокоды, канал, описание |
| `/розыгрыш быстрый` | розыгрыш по шаблону из панели, остаётся вставить промокоды |
| `/розыгрыш завершить` | подвести итоги досрочно |
| `/розыгрыш реролл` | перевыбрать победителей; им достаются невыданные и недоставленные промокоды |
| `/розыгрыш промокоды` | кому какой промокод достался, повторная отправка недоставленных |
| `/розыгрыш отменить` | отменить без итогов |
| `/розыгрыш список` | активные розыгрыши |

В панели, раздел «Розыгрыши»: создание розыгрыша (бот отправит его в канал в течение 10 секунд), все розыгрыши
с участниками, победителями и промокодами, досрочные итоги и отмена, часовой пояс, текст сообщения победителю
и шаблон быстрого розыгрыша.

1. Боту нужно своё приложение в Discord Developer Portal, не то же, что у Scrap Rank: команды двух ботов с одним токеном затирали бы друг друга. Если бот розыгрышей уже работал на Python, возьми его приложение. Привилегированные интенты не нужны.
2. В панели открой «Розыгрыши» → «Подключение» и вставь токен бота (Bot → Reset Token). Панель проверит токен в Discord,
   а бот подключится сам в течение 10 секунд. Там же появится кнопка «Пригласить на сервер» с нужными правами:
   просмотр каналов, отправка сообщений, встраивание ссылок, чтение истории сообщений.
3. `docker compose up -d --build`.

### Переезд с прежнего бота на Python

История розыгрышей переносится из его базы `data/giveaways.db` одной командой. Номера розыгрышей сохраняются.

1. Останови прежнего бота, иначе итоги будут подводить два бота сразу.
2. Положи `giveaways.db` рядом с `docker-compose.yml` и запусти импорт (база уже должна быть создана, то есть стек хотя бы раз запускался):

   ```bash
   docker compose run --rm -v ./giveaways.db:/import/giveaways.db:ro migrate pnpm -F giveaway-bot import-sqlite /import/giveaways.db
   ```

3. Дай новому боту токен прежнего: только автор сообщения может его менять, поэтому старые розыгрыши (реролл, отмена) продолжит тот же бот.
4. Удали `giveaways.db` из папки: в ней промокоды.

Импорт делается один раз в пустую таблицу. Если розыгрыши уже есть, команда ничего не меняет.

## Бот карт вайпов

Раньше это был отдельный бот на Python с управлением в Telegram. Теперь он часть системы: всё настраивается в панели
(«Карты вайпов»), а Telegram остаётся вторым пультом — те же карточки карт, кнопки и команды
`/next /status /gen /reset /upload /discord /resend /panel /global /auto`. Логика одна, в боте: что сделано в панели,
сразу видно в Telegram, и наоборот.

Как устроен вайп: за «Анонс» + «Генерация» часов до вайпа бот заказывает пул карт по сохранённым конфигам RustMaps,
раздаёт серверам лучшие по оценке (или предлагает набор целиком при автоподборе). Подтверждённые карты скачиваются
и заливаются в S3, когда подтверждены все — анонс уходит в Discord в назначенное время. За несколько часов до вайпа
бот спрашивает про запись ссылок в Pterodactyl и записывает их сам, если никто не ответил.

В панели:

- **Обзор** — что не настроено, вайпы в работе, ближайшие вайпы с кнопкой «Сгенерировать сейчас», автоподбор.
- **Вайпы и карты** — карты серверов с оценкой и чек-листом РТ: подтвердить, заменить, вернуть предыдущую, своя карта
  по ссылке; автоподбор; снять подтверждения или заменить все; анонс в Discord; ссылки в Pterodactyl.
- **Серверы**, **Расписание** (дни, время, пулы, шаблоны анонса, форс-вайп, глобальные вайпы), **Оценка карт** (веса),
  **Настройки** (тайминги, Telegram-админы, S3, Pterodactyl).
- **Подключение** (только администраторам) — ключ RustMaps, ключи S3, вебхук Discord, токен Telegram, ключ Pterodactyl
  и «Проверить подключения». Ключи шифруются ключом бота: прочитать их не может ни панель, ни тот, кто украдёт базу.

Своя карта файлом до 20 МБ загружается через Telegram (лимит Telegram для ботов), по ссылке — и в панели, и в Telegram.

### Переезд с прежнего бота на Python

Одна команда переносит историю (вайпы, карты, пул; номера сохраняются, старые карточки в Telegram продолжат работать)
и, если указать `--env`, настройки и ключи из его `.env`. Ключи сразу шифруются ключом нового бота и нигде не выводятся.

1. Обнови стек, чтобы бот карт хоть раз запустился (`./deploy/update.sh` или `docker compose up -d --build`):
   без этого нет ключа шифрования.
2. Останови прежнего бота. Лучше сразу после ближайшего вайпа: иначе запись ссылок в Pterodactyl и анонс
   сделают оба бота, а Telegram отдаёт обновления только одному из них.
3. Положи рядом с `docker-compose.yml` его `data/bot.sqlite3` и `.env` и запусти импорт:

   ```bash
   docker compose run --rm -v ./bot.sqlite3:/import/bot.sqlite3:ro -v ./old.env:/import/old.env:ro migrate pnpm -F maps-bot import-sqlite /import/bot.sqlite3 --env /import/old.env
   ```

4. Удали `bot.sqlite3` и `old.env` из папки: в `.env` ключи в открытом виде.
5. В панели: «Карты вайпов» → «Подключение» → «Проверить подключения».

Импорт делается один раз в пустые таблицы. Серверы, расписание и шаблоны анонса создаются такими же, как были
в коде прежнего бота, дальше они меняются в панели.

## Бот онлайна серверов

1. Для каждого игрового сервера создай отдельное приложение в Discord Developer Portal и скопируй токен его бота. Приглашать на сервер можно без прав: бот только показывает статус.
2. Запусти бота (`docker compose up -d --build`), открой в панели «Онлайн серверов» → «Серверы» → «Добавить сервер» и введи адрес, порт RCON, пароль RCON и токен.

Пароль RCON и токен шифруются открытым ключом бота прямо при сохранении. Прочитать их может только сам бот: в панели их видно, пока вводишь, а после сохранения — только отметка «Сохранён» и кнопка «Заменить». Ключ шифрования бот создаёт сам при первом запуске и хранит в своём томе Docker (`online-bot-data`). Если потерять том, секреты придётся ввести заново.

### Уведомления в Telegram

Бот присылает в Telegram сообщение, когда сервер выключился и когда снова заработал.

1. Создай отдельного бота в @BotFather: тот, что подключён к боту карт, не подойдёт, панель его не примет.
2. Администратор сервера вставляет токен в «Онлайн серверов» → «Telegram» → «Подключение». Токен шифруется ключом бота онлайна, как пароли RCON.
3. Напиши боту `/id` в личке (или добавь его в группу или канал и напиши там): он ответит ID чата. Вставь ID в «Получатели», сохрани и нажми «Отправить пробное».

Короткий обрыв не тревога: сообщение о выключении уходит, только если сервер не отвечает дольше времени ожидания (по умолчанию 60 секунд).
Сообщение о включении приходит, если перед этим сервер лежал дольше этого времени, с указанием, сколько он не работал.
Что уже отправлено, хранится в базе, поэтому после перезапуска бота уведомления не повторяются и не теряются.

## Настройка Discord-приложения

1. Создай приложение на <https://discord.com/developers/applications>.
2. **OAuth2**: Client ID и Client Secret нужны для входа в панель, их спросит мастер `./deploy/init-env.sh`. В Redirects добавь `<PANEL_URL>/api/auth/callback`, например `https://panel.example.com/api/auth/callback`.
3. **Bot**: включи **Message Content Intent** (без него бот не видит длину сообщений) и выключи **Public Bot**, чтобы бота не мог добавить кто угодно. Нажми Reset Token.
4. Войди в панель, открой «Рейтинг участников» → «Подключение» и вставь токен. Токен шифруется ключом самого бота: после сохранения его не прочитает ни панель, ни тот, у кого окажется копия базы. Там же кнопка «Пригласить на сервер» с правами: просмотр каналов, отправка сообщений, встраивание ссылок, прикрепление файлов, управление ролями.
5. В настройках сервера перетащи роль бота **выше** ролей рангов и ролей из магазина, иначе он не сможет их выдавать.

## Локальная разработка

Нужны Node.js 22+, pnpm 10 и PostgreSQL (проще всего в Docker).

```bash
./deploy/init-env.sh
```

Мастер спросит данные приложения Discord и сам сгенерирует секреты. Для базы в Docker:

```bash
docker run -d --name flamebot-pg -e POSTGRES_USER=flamebot -e POSTGRES_PASSWORD=devpass -e POSTGRES_DB=flamebot -p 127.0.0.1:5432:5432 postgres:17-alpine
```

и `DATABASE_URL=postgresql://flamebot:devpass@localhost:5432/flamebot`.

```bash
pnpm install
pnpm db:deploy
pnpm dev:rating-bot
pnpm dev:giveaway-bot
pnpm dev:maps-bot
pnpm dev:panel
```

Слэш-команды бот регистрирует на сервере сам при каждом запуске.

Панель откроется на <http://localhost:3000>. Войти могут владелец сервера, роли с правом «Администратор» или «Управлять сервером» и роли, отмеченные на странице «Доступ». Бот должен хотя бы раз запуститься: панель проверяет права по снимку ролей, который он записывает.

Проверки перед коммитом:

```bash
pnpm typecheck
pnpm test
```

## Запуск на сервере

Пошаговая инструкция для VPS на Ubuntu — в [docs/DEPLOY.md](docs/DEPLOY.md): подготовка сервера одним скриптом,
HTTPS через Caddy, перенос базы с ПК, тестовая копия на ветке `dev` и автодеплой из GitHub.

Коротко: на сервере обновление — одна команда, она делает резервную копию базы, собирает новую версию,
проверяет её и при ошибке возвращает прошлую:

```bash
./deploy/update.sh
```

## Как подключить нового бота

1. Добавь таблицы бота в `packages/core/prisma/schema.prisma` отдельным разделом и создай миграцию: `pnpm db:migrate`.
2. Создай приложение в `apps/<имя-бота>/` по образцу `apps/rating-bot`. Бот должен раз в минуту отмечаться в таблице `BotStatus` под своим ключом.
3. Добавь страницы в `apps/panel/src/app/(panel)/<ключ>/` и опиши модуль в `apps/panel/src/modules/index.ts`. Главная, меню, журнал и доступ подхватят его сами.
4. Добавь сервис в `docker-compose.yml`.

## Безопасность

Подробности в [SECURITY.md](SECURITY.md). Главное правило: репозиторий публичный, секреты живут только в `.env` на сервере, а токены ботов в базе, зашифрованными ключами ботов.

# Безопасность

## Сообщить об уязвимости

Не открывай публичный issue. Напиши владельцу репозитория в личные сообщения Discord или через приватный [Security Advisory](https://github.com/ReDcTiOn/flamebot-discord/security/advisories/new).

## Секреты

- Секреты инфраструктуры (пароль базы, секрет сессий, данные входа в панель) только в `.env`, который не попадает в git. Репозиторий публичный.
- Токены ботов Discord вводятся в панели (раздел «Подключение», только для администраторов) и хранятся в базе зашифрованными ключом бота, см. ниже.
- Если токен или секрет хоть раз попал в коммит, issue или скриншот, сразу смени его в Discord Developer Portal. Удаление из истории git не помогает: его уже могли скопировать.
- Каждый сервис получает только свои секреты. Боты не знают `DISCORD_CLIENT_SECRET` и `SESSION_SECRET`, панель не может прочитать ни одного токена бота.

## Что защищает панель

| Угроза | Защита |
|---|---|
| Вход без прав | Вход только через Discord OAuth. Доступ есть у владельца сервера, ролей с правом «Администратор» или «Управлять сервером» и ролей из списка на странице «Доступ». Управлять доступом могут только владелец и администраторы. Владельца и права панель берёт у самого Discord при входе (список серверов пользователя), поэтому вход работает и на чистой установке, пока бот ещё не подключён. |
| Потеря прав | Права перепроверяются в Discord каждые 5 минут. Сняли роль или выгнали с сервера — сессия завершается. Сессия живёт не больше 12 часов. |
| Подделка входа (CSRF на OAuth) | Одноразовый `state` в httpOnly-cookie, сравнение за постоянное время. |
| Кража сессии | Cookie `httpOnly`, `SameSite=Lax`, на HTTPS `Secure` и префикс `__Host-`. В базе хранится только SHA-256 от токена сессии, OAuth-токен Discord зашифрован AES-256-GCM. Владелец может завершить все чужие сессии одной кнопкой. |
| CSRF на изменение настроек | Все изменения идут через server actions Next.js, которые отклоняют запросы с чужим `Origin`. |
| Обход проверок через прокси | Права проверяются в каждой странице и каждом действии, а не только в `proxy.ts`. |
| XSS и встраивание в чужой сайт | Content-Security-Policy с nonce и `strict-dynamic`, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, React экранирует вывод. |
| Перебор и спам | Ограничение частоты на вход (10 в минуту с IP) и на действия (60 в минуту на человека). |
| Некорректные данные | Все поля проверяются zod-схемами из `packages/core` с жёсткими границами. ID ролей и каналов сверяются со снимком сервера. |
| Загрузка картинок | Только PNG, JPEG и WebP до 5 МБ. Размеры проверяются по заголовку до декодирования (защита от «бомб»), затем картинка перерисовывается на чистом холсте и сохраняется заново: метаданные и вложенные данные не проходят. Картинки отдаются только вошедшим, с `nosniff` и `sandbox`. |
| Шаблон карточки | Шаблон проверяется схемой с жёсткими границами размеров и числа элементов, в боте рисуется только по этой схеме. Внешние адреса картинок не принимаются, аватар берётся только с CDN Discord. |
| Скрытые правки | Каждое изменение, вход, отказ во входе и выход пишутся в журнал. Из интерфейса журнал не редактируется. |

## Секреты ботов в панели

Токены ботов рейтинга и розыгрышей, пароли RCON и токены ботов онлайна, токен Telegram-бота уведомлений об онлайне, ключи бота карт (RustMaps, S3, Pterodactyl, вебхук Discord, токен Telegram), ключи бота объявлений (токен Telegram, вебхуки Discord, ключи ВКонтакте, секретный ключ gamestores) вводятся в панели, но панель их не хранит в открытом виде и не умеет читать:

- каждый бот при первом запуске создаёт себе ключ X25519 и хранит приватную часть в своём томе Docker (`/data`, права 600). В базу попадает только открытая часть;
- панель шифрует секрет открытым ключом бота (X25519 + HKDF-SHA256 + AES-256-GCM) и сразу кладёт в базу. Приватного ключа у панели нет;
- каждый шифротекст привязан к боту, серверу и полю: его нельзя переставить другому боту или в другое поле;
- перед сохранением панель проверяет токен в Discord и не даёт подключить одно приложение Discord к двум модулям;
- менять токены могут только администраторы; в журнал пишется, кто и какого бота подключил, без значения;
- украденная база или взломанная панель не раскрывают ни одного токена: для этого нужен ещё том бота;
- если токен утёк, его можно удалить в панели одной кнопкой, бот сразу отключится.

Тома с ключами в резервные копии базы не попадают, и это намеренно: копия базы вместе с ключами раскрыла бы токены. Если том потерян, токены вводятся в панели заново.

В панель намеренно не вынесены секреты, без которых в неё нельзя войти (данные OAuth, `SESSION_SECRET`), пароль базы и `ALLOW_PRIVATE_RCON`: взломанная панель не должна открывать доступ к внутренней сети сервера.

Бот онлайна не подключается к внутренним адресам (localhost, локальная сеть, сеть Docker), даже если их указать в панели: адрес проверяется после DNS. Разрешить можно только явно через `ALLOW_PRIVATE_RCON=true`.

## Бот карт

- Ключи бота карт шифруются так же, как токены остальных ботов. В панели видна только подсказка (последние символы, номер вебхука), сами значения не показываются и не пишутся ни в журнал, ни в историю.
- Нажимать кнопки в Telegram и писать боту могут только Telegram ID из списка админов в настройках; остальным бот не отвечает.
- Действия из панели бот выполняет тем же кодом, что и кнопки Telegram, по заданиям в базе. Список заданий закрыт: панель не может попросить бота сделать что-то, кроме действий с картами.
- Подпись запросов к S3 (SigV4) — без сторонних библиотек; файл карты проверяется по размеру после загрузки и по публичной ссылке CDN.

## Бот объявлений

- Ключи шифруются так же, как у остальных ботов; в панели видна только подсказка.
- Нажимать кнопки и писать боту в Telegram могут только Telegram ID из списка админов.
- Один Telegram-бот нельзя подключить к двум модулям (карты, онлайн, объявления): панель сверяет номер бота.
- Картинки постов панель перерисовывает на чистом холсте: метаданные и чужие вложения в файле не сохраняются. Отдаёт их только вошедшим в панель.
- Список заданий боту из панели закрыт: подтвердить, сменить текст, отменить, повторить, тест, проверка подключений и список промокодов.
- Тестовые прогоны не трогают боевой магазин: промокод создаётся только с префиксом TEST-, скидкой 1% и одним использованием, и только если это включено в настройках.

## Промокоды розыгрышей

Промокоды стоят денег, поэтому:

- в панели сами коды видят только администраторы сервера, остальные с доступом к панели видят, кому и дошёл ли промокод;
- в историю событий бота промокоды не пишутся, только факт отправки;
- в Discord полный список кодов получает только организатор розыгрыша: в ЛС и в ответах, которые видит он один.

## Что защищает бот

| Угроза | Защита |
|---|---|
| Выдача модерки или админки | Бот никогда не выдаёт роли с правами модерации или администрирования, служебные роли и `@everyone`. Проверка есть и в панели, и в боте по живым данным Discord, поэтому даже взломанная панель не раздаст опасную роль. |
| Массовые пинги | По умолчанию бот никого не упоминает. В объявлении о ранге разрешено упоминание только самого игрока, `@everyone` из шаблона не сработает. |
| Двойные покупки и уход в минус | Покупки и `/rep` выполняются по очереди для каждого игрока. Списание скрапа — одна SQL-операция с условием `scrap >= price`. Если товар не удалось выдать, скрап возвращается. |
| Личная роль без проверки | По умолчанию каждая личная роль сначала приходит заявкой в выбранный канал. Решать могут только администраторы, «Управление ролями» и роли с доступом к панели. При отказе скрап возвращается. |
| Личная роль под видом админа | Название очищается от упоминаний и невидимых символов, запрещены слова вроде «админ», «модер», «support» и совпадения с существующими ролями. Права у роли нулевые. |
| Накрутка опыта | Кулдаун, минимальная длина сообщения, опыт только в выбранных каналах. Репутацию нельзя дать себе, ботам и новичкам на сервере; есть лимит на частоту и на повтор одному игроку. |
| Использование бота на чужом сервере | Бот работает только на `GUILD_ID` и сразу выходит с любого другого сервера. В Developer Portal выключи Public Bot. |
| Лишние права | Бот запрашивает только нужные intents и права: просмотр каналов, сообщения, встраивание ссылок, файлы, управление ролями. |

## Инфраструктура

- PostgreSQL не публикуется наружу: он в изолированной сети compose.
- Панель слушает только `127.0.0.1`, наружу её выставляет reverse proxy с HTTPS.
- Контейнеры работают от непривилегированного пользователя, с read-only файловой системой, `no-new-privileges` и без Linux capabilities.
- Dependabot следит за зависимостями, CI запускает `pnpm audit` на каждый push.

## Что остаётся на тебе

- Включить двухфакторную аутентификацию в Discord и на GitHub для всех, у кого есть доступ.
- Держать роль бота ниже ролей модерации, но выше ролей рангов и магазина.
- Ставить обновления зависимостей, которые приносит Dependabot.
- Делать резервные копии базы: `docker compose exec db pg_dump -U flamebot flamebot > backup.sql`.
